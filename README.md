# NSI: ALFWorld and TextCraft source release

This directory contains the public source implementation of
**Neuro-Symbolic Induction (NSI)**.

## Method name

The method released here is **NSI**. Use this name in papers, reports, issues,
and derived work. Some internal module names, class attributes, and generated
trial-directory prefixes still contain `nsms` for backward compatibility with
the research code. Those identifiers refer to the NSI implementation; **NSMS is
not a second method or an alternative public name**.

## Release scope

Included:

- the NSI agents, symbolic state trackers, workflow parser, and evaluators;
- ALFWorld and TextCraft adapters and command-line entry points;
- the small demonstration sets required to induce skills from scratch;
- the required [Concepts](https://github.com/concepts-ai/Concepts) DSL subset and its upstream license;
- two metadata-free Mermaid workflows under `skill_examples/` as format
  examples.

The files under `skill_examples/` are illustrative outputs only. The runners
do not load them. Reproduction starts from the bundled demonstrations and
generates a new local NSI state.

## 1. Install

Run all commands below from this directory. Python 3.10 is recommended.

With Conda:

```bash
conda env create -f environment.yml
conda activate nesy-release
pip install -e . --no-deps
```

Or with a virtual environment:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e .
```

The editable install makes the package importable and installs the
`nesy-alfworld` and `nesy-textcraft` commands.

Set the language-model credential:

```bash
export OPENAI_API_KEY=...
```

The released configuration defaults to `gpt-4o` with temperature `0.0`.
Select another available model with `--llm` if necessary. Model calls are made
during both induction and evaluation and may incur substantial API cost.

### ALFWorld data

Download ALFWorld data with its upstream command:		

```bash
alfworld-download
```

Then point `ALFWORLD_DATA` at the downloaded data root. That root must contain
`json_2.1.1/` and `logic/`:

```bash
export ALFWORLD_DATA=/absolute/path/to/alfworld/data

test -d "$ALFWORLD_DATA/json_2.1.1/valid_unseen"
test -f "$ALFWORLD_DATA/logic/alfred.pddl"
```

TextCraft data are provided by the installed `textcraft` package and require
no separate environment variable.

## 2. Verify the installation

```bash
nesy-alfworld --help
nesy-textcraft --help
```

The help commands do not make model calls or start benchmark episodes.

## 3. Induce and evaluate from scratch

Do not pass `--load_skill`, `--load_call`, or `--all_ready` on the first
run. The first invocation:

1. grounds the bundled demonstrations;
2. builds trajectory and skill-calling memories;
3. induces and validates symbolic workflows;
4. writes the generated NSI state under `outputs/`;
5. evaluates the requested environment range.

The canonical offline runs induce NSI state once and then evaluate the complete
benchmark range in the same process.

ALFWorld:

```bash
python run_alfworld.py \
  --trial_name alfworld_local \
  --induction_mode ilp \
  --start_index 0 \
  --num_envs 134 \
  --force_run
```

TextCraft:

```bash
python run_textcraft.py \
  --trial_name textcraft_local \
  --start_index 0 \
  --num_envs 200 \
  --force_run
```

`--force_run` keeps a multi-environment evaluation running when an isolated
episode raises an exception. For a short pipeline check, reduce `--num_envs`
without changing the canonical commands above.

With the default model, these commands write to:

- `outputs/alfworld/nsms_gpt-4o_alfworld_local/`;
- `outputs/textcraft/nsms_gpt-4o_textcraft_local/`.

The `nsms_` directory prefix is a legacy internal identifier described in
[Method name](#method-name); both directories contain NSI runs. If `--llm` is
changed, the model name in the directory changes as well.

Check that induction and offline evaluation completed:

```bash
ALF_TRIAL=outputs/alfworld/nsms_gpt-4o_alfworld_local
TEXT_TRIAL=outputs/textcraft/nsms_gpt-4o_textcraft_local

test -s "$ALF_TRIAL/skill_json_file_for_run.json"
test -s "$ALF_TRIAL/alfworld_results.csv"
find "$ALF_TRIAL/ilp_workflow" -name '*_valid.mmd' -print

test -s "$TEXT_TRIAL/skill_json_file_for_run.json"
test -s "$TEXT_TRIAL/textcraft_results.csv"
find "$TEXT_TRIAL/ilp_workflow" -name '*_valid.mmd' -print
```

A missing state file means induction did not finish successfully; inspect the
terminal error and the local `agent_log/` directory before continuing.

## 4. Optional online skill evolution

Online evolution must load an NSI state generated by Section 3. In particular,
do not add `--online` to the first TextCraft invocation. Use a separate trial
directory so offline and online result rows are not mixed.

The following Bash helper copies only the locally generated induction state,
not prior evaluation results or logs:

```bash
copy_nsi_state() {
  src="$1"
  dst="$2"
  mkdir -p "$dst"
  cp "$src"/{trajectory_memory_graph.json,sub_goals.json,skill_calling_memory_graph.json,skill_json_file_for_run.json,skill_memory_blocks_with_task_type.json,revised_calling_memory.json,task_level_guidelines.json} "$dst"/
  cp -R "$src"/{grounding_examples,ilp_workflow} "$dst"/
}

copy_nsi_state \
  outputs/alfworld/nsms_gpt-4o_alfworld_local \
  outputs/alfworld/nsms_gpt-4o_alfworld_online

copy_nsi_state \
  outputs/textcraft/nsms_gpt-4o_textcraft_local \
  outputs/textcraft/nsms_gpt-4o_textcraft_online
```

Run online evaluation from the copied states:

```bash
python run_alfworld.py \
  --trial_name alfworld_online \
  --induction_mode ilp \
  --load_skill --load_call --all_ready --online_mode \
  --start_index 0 --num_envs 134 --force_run
```

```bash
python run_textcraft.py \
  --trial_name textcraft_online \
  --load_skill --load_call --all_ready --online \
  --start_index 0 --num_envs 200 --force_run
```

Online products are generated locally under each trial's
`online_evolved/` directory.

## Reproducibility notes

- The first successful run performs model calls and creates a local NSI state.
- Temperature is fixed at `0.0` by default, but hosted model behavior and
  upstream benchmark packages can still introduce variation.
- Keep the model name, dependency versions, split, start index, and environment
  count fixed when comparing runs.
- Generated state, trajectories, logs, and results are written under
  `outputs/`.
